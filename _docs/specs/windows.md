# Windows

Належить App. Роадмап: [app](../roadmaps/app.md).

**поза релізом.** `go build` під `windows/amd64` проходить. Запуску на Windows не було. Асет Windows у перший Release не кладемо. Ставлять командою `install.sh`, не кнопкою Download. Скрипт цей асет не пропонує.

## Знайдене в коді

1. `processIsRunning` шле `Signal(0)`. На Windows це помилка, тож живі сесії списуються як мертві.
2. Парсери front matter чекають `---\n`. З `autocrlf=true` файли стають `---\r\n`, і задачі виглядають порожніми.
3. Пошук Claude, Cursor і Codex прив'язаний до шляхів macOS. На Windows лишається `PATH`. Агенти з npm — це `.cmd`, не `.exe`.
4. Багаторядковий промпт через `.cmd` / `cmd.exe` не перевірений. Ліміт командного рядка близько 32 КБ.
5. Зупинка процесу вбиває прямий процес. Для `.cmd` це `cmd.exe`, дочірній `node` лишається.
6. Частина шляхів ріжеться по `"/"`. Регістр, UNC, довжина понад 260 і зарезервовані імена не розібрані.
7. `~` розгортається лише як `~/`.
8. Розбір рядків по `\n` лишає `\r`. Кодова сторінка консолі може бути не UTF-8.
9. Частина тестів піднімає фейкових агентів як `#!/bin/sh`. CI лише компілює під Windows, тести там не біжать.

Окремо невідомо, чи самі CLI агентів працюють на Windows поза WSL. Без них збірка App марна.

## Коли повертатися

Після macOS-релізу, окремим проходом: CRLF у двох парсерах, liveness через Windows API, пошук агентів, Windows CI, прогін `.cmd` із багаторядковим промптом. До цього в [release](../roadmaps/release.md) Windows-асета немає.
