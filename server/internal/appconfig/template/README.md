# Data

Your own operating data: raw inputs, projects/tasks, worker definitions,
archive, and the generated project registry. Bootstrapped automatically by
Fleet on first run — see `AGENTS.md` for the rules Fleet itself follows here.

## Shape

```text
Data
|-- Inbox/       raw incoming items before classification
|-- Work/        project/workspace folders with a project card and tasks
|-- Fleet/       workers: humans, AI agents, tools, and execution surfaces
|-- Archive/     closed, superseded, or intentionally ignored material
|-- _registry/   deterministic machine-readable state generated by Fleet's scan
|-- _docs/       your own operating notes for this data root
`-- AGENTS.md    canonical agent instruction file for this tree
```

`fleet serve` adds the Manager files when they are needed:

- `.agents/skills/`, the Manager skills, with a pointer in `.claude/skills`,
  `.codex/skills`, `.gemini/skills`, and `.cursor/rules`;
- when you create a Manager session, the Fleet MCP entry in `.mcp.json` (Claude),
  `.codex/config.toml` (Codex), `.cursor/mcp.json` (Cursor), and
  `.agents/mcp_config.json` (Gemini). The entry carries a per-install token, so
  do not publish those files.

This template is the generic bootstrap. An operator's Data copy may diverge from it. The human worker here is `owner`. A person is a worker, and can be assigned tasks, when `Fleet/<name>.md` exists.

The Manager is a Claude, Codex, Cursor, or Gemini session whose folder is
this directory. The conversation stays in that provider's app. Each provider
loads Fleet MCP from its own file above. `fleet serve` must be running.

Fleet is pointed at this directory with `--root`, a saved app config, or its
default location — see the app's own Settings for how to view or change it.
